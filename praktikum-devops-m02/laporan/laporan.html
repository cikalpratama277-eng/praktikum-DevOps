2. Dasar Teori Ringkas

Linux adalah substrat kerja DevOps: Docker, Kubernetes, Terraform, Ansible, hingga runner CI/CD berjalan native di atas kernel Linux dan dikelola lewat CLI, bukan GUI. Dua pilar interaksinya:

  • Filesystem Hierarchy Standard (FHS) — satu pohon tunggal berakar /. /etc (konfigurasi), /var/log (log — sumber observability), /usr/bin (biner CLI), /tmp (artefak sementara CI/CD). Standarisasi inilah yang membuat skrip berpindah dari laptop ke server/kontainer tanpa mengubah path.
  • Ownership & Permissions — entitas User/Group/Other dengan izin r(4)/w(2)/x(1). Lahir prinsip Least Privilege: beri izin seminimal mungkin. Anti-pola berbahaya: chmod 777 dan menjalankan aplikasi/kontainer sebagai root.

Filosofi Unix "do one thing and do it well" + operator aliran data: pipe (|), redirection (> timpa, >> tambah), dan stream merging (2>&1) menyambung program kecil menjadi "mesin analitik" log.

Kontrak Exit Code: 0 = sukses; non-nol = gagal. Runner CI/CD tidak melihat tampilan — mereka membaca exit code. Anti-pola "membutakan pipeline" (|| true atau memaksa exit 0) membuat runner menganggap semua lulus meski tes gagal. Karena itu set -euo pipefail + trap, pustaka fungsi bersama, logging terstruktur, idempotensi, dan analisis statis menjadikan shell script bentuk paling awal Infrastructure as Code.

3.1 JOB 1 — Struktur Berkas, Kepemilikan & Izin Akses

Identitas, umask, dan percobaan izin pada berkas yang mensimulasikan kredensial (keluaran nyata):

$ id
uid=0(root) gid=0(root) groups=0(root)
$ umask
0022
$ df -h /
Filesystem      Size  Used Avail Use% Mounted on
overlay          95G   19G   77G  20% /

--- percobaan izin akses ---
$ stat -c '%a %U:%G %n' kredensial-latihan.txt   (default, dipengaruhi umask 0022)
644 root:root kredensial-latihan.txt
$ chmod 600 ; stat ...        -> 600 root:root   (least privilege)
$ chmod u+x,go-rwx ; stat ... -> 700 root:root   (notasi simbolik)
$ chmod 600 (kembalikan aman) -> 600 root:root

Interpretasi digit izin. 644 = rw-r--r-- (pemilik baca+tulis; grup & other hanya baca). 600 = rw------- (hanya pemilik; grup & other kehilangan akses baca — tepat untuk berkas kredensial). umask 0022 menjelaskan mengapa berkas baru tidak pernah langsung punya izin eksekusi: bit x di-mask, selaras least privilege.

Catatan: lingkungan eksekusi berjalan sebagai root; pada mesin mahasiswa id & pemilik berkas akan menampilkan akun Anda (mis. cikal).

5. Jawaban Pertanyaan Analisis (4.1)

5.1 Batas kemampuan set -e

Meski skrip memuat set -euo pipefail, perintah gagal tidak selalu menghentikan eksekusi. Minimal dua situasi:

  1. Di dalam kondisi if/while atau sisi kiri && / ||. Status gagal di konteks ini "dikonsumsi" sebagai nilai boolean, jadi set -e diabaikan. Contoh: if grep xyz f; then ... tidak berhenti walau grep gagal. Penanganan: tangani eksplisit — if ! cmd; then die "..."; fi, sehingga kegagalan jadi keputusan sadar, bukan lolos diam-diam.
  2. Pada command substitution di penugasan variabel, mis. out="$(cmd_gagal)". Pada banyak kondisi, status keluar penugasan = status local/assignment, bukan cmd, sehingga skrip jalan terus dengan out kosong. Penanganan: pisahkan deklarasi & penugasan lalu periksa — local out; out="$(cmd)" || die "gagal" (pola ini juga alasan shellcheck SC2155 menyarankan memisah declare dari assignment, seperti yang saya terapkan pada sysreport.sh).

Situasi lain: perintah di dalam pipe selain yang terakhir (ditangani pipefail), dan fungsi yang dipanggil di konteks kondisi.

5.2 Agregat yang menyesatkan

Proksi Change Failure Rate = 18,40% (92 dari 500). Angka agregat tunggal ini menyesatkan karena menyamarkan sebaran per endpoint: dari JOB 2, kegagalan ≥500 terkonsentrasi di /health (30) dan /api/users (23), sementara /api/orders (18) relatif lebih rendah. Jika tim hanya melihat "18%", mereka tidak tahu harus memperbaiki yang mana lebih dulu. Metrik tambahan yang lebih berguna: failure rate per endpoint = (jumlah ≥500 pada endpoint ÷ total permintaan endpoint) × 100% — mengurutkan prioritas perbaikan ke endpoint dengan rasio gagal tertinggi relatif terhadap trafiknya. (Alternatif lain: error-count berbobot latensi, agar endpoint lambat dan gagal naik prioritas.)

5.3 CLI versus GUI

CLI menjadi prasyarat otomasi karena tiga sifat:

  • Reproducibility — perintah/skrip memberi hasil sama di mesin mana pun (berkat FHS & exit code), berbeda dengan klik GUI yang sulit diulang persis.
  • Auditability — setiap perintah terekam (history, log terstruktur, diff commit); siapa mengubah apa dapat ditelusuri.
  • Version control — skrip adalah teks yang bisa di-diff, ditinjau via pull request, dan di-rollback — fondasi Infrastructure as Code.

Situasi GUI tetap lebih tepat: eksplorasi/analisis visual data yang belum terstruktur — mis. membaca dashboard observability (Grafana) untuk mengenali pola anomali lintas waktu, atau desain antarmuka. Di sini persepsi visual manusia lebih cepat daripada membaca angka mentah di terminal.

5.4 Least privilege pada otomasi

Saran menjalankan setup.sh dengan sudo + memberi chmod 777 pada seluruh direktori aplikasi berbahaya:

  • Risiko 777: setiap pengguna/proses (termasuk malware yang berhasil masuk) dapat menulis ulang kode sumber, membaca berkas kredensial, atau menyisipkan backdoor — pelanggaran total least privilege.
  • Risiko sudo/root: bila aplikasi punya celah (mis. RCE), penyerang otomatis memperoleh hak setingkat administrator atas host.

Dua mekanisme pengganti yang menyelesaikan "Permission denied" tanpa menaikkan hak:

  1. Kepemilikan yang benar + izin minimal — jadikan user aplikasi sebagai pemilik direktori lalu chmod 750 (atau 700 untuk berkas rahasia 600). Masalah akses selesai tanpa membuka ke "Other".
  2. Isolasi lingkungan per-pengguna — gunakan virtual environment di direktori milik user (seperti .venv pada skrip ini) sehingga instalasi dependensi tidak butuh akses global/sudo sama sekali (menghindari galat externally-managed-environment).

5.5 Idempotensi

Masing-masing skrip dijalankan tiga kali berturut-turut:

SkripIdempotent?Bukti/alasan
sysreport.shYABersifat read-only (hanya membaca df/free/ps). Tiga kali eksekusi memberi struktur keluaran & exit code sama (0); tidak mengubah state sistem.
setup.shSebagian / terjagaPembuatan venv & instalasi dipandu guard ([ -d .venv ] ||, pin versi) sehingga aman diulang. Namun langkah "jalankan app" mengikat port; eksekusi kedua saat app masih hidup gagal cepat lewat port_is_free ... || die — gagal terkendali, bukan merusak state.

Idempotensi menjadi syarat mutlak pada Infrastructure as Code (minggu ke-12): tool seperti Ansible/Terraform menjalankan deklarasi berulang kali dan harus konvergen ke state yang sama tanpa efek samping ganda. Skrip yang tidak idempotent akan menggandakan sumber daya atau merusak konfigurasi saat dijalankan ulang oleh pipeline.

Lampiran B.1 — buat-log.sh

#!/usr/bin/env bash
# buat-log.sh — Generator log sintetis (reproducible) untuk latihan analisis.
set -euo pipefail
OUT="${1:-app.log}"
IPS=(10.10.0.11 10.10.0.12 10.10.0.13 172.16.4.7 192.168.5.20)
PATHS=(/health /api/orders /api/users /static/app.js)
CODES=(200 200 200 200 201 301 404 404 500 502)
: > "$OUT"
for _ in $(seq 1 500); do
  ts=$(date -d "-$((RANDOM % 1440)) minutes" '+%d/%b/%Y:%H:%M:%S %z')
  ip=${IPS[$((RANDOM % ${#IPS[@]}))]}
  p=${PATHS[$((RANDOM % ${#PATHS[@]}))]}
  c=${CODES[$((RANDOM % ${#CODES[@]}))]}
  ms=$((RANDOM % 1200 + 5))
  echo "$ip - - [$ts] \"GET $p HTTP/1.1\" $c $ms" >> "$OUT"
done
echo "Dibuat: $OUT ($(wc -l < "$OUT") baris)"

Lampiran B.2 — sysreport.sh

#!/usr/bin/env bash
# sysreport.sh — Laporan kesehatan sistem ringkas untuk kebutuhan operasional.
set -euo pipefail
SCRIPT_NAME="$(basename "$0")"; readonly SCRIPT_NAME
readonly VERSION="1.0.0"
THRESHOLD_DISK=80
FORMAT="text"
log() { printf '[%s] %s\n' "$(date '+%H:%M:%S')" "$*" >&2; }
die() { log "GALAT: $*"; exit 1; }
usage() {
  cat <<USAGE
$SCRIPT_NAME v$VERSION — laporan kesehatan sistem
Penggunaan: $SCRIPT_NAME [OPSI]
  -d N   Ambang peringatan pemakaian disk dalam persen (default: 80)
  -j     Keluarkan hasil dalam format JSON
  -h     Tampilkan bantuan ini
Exit code: 0 = sehat, 2 = melewati ambang, 1 = galat penggunaan
USAGE
}
disk_usage_pct() { df -P / | awk 'NR==2 { gsub("%","",$5); print $5 }'; }
mem_used_pct()  { free | awk '/^Mem:/ { printf "%.0f", $3/$2*100 }'; }
proc_count()    { ps -e --no-headers | wc -l; }
main() {
  local disk mem procs status opt
  while getopts ":d:jh" opt; do
    case "$opt" in
      d) THRESHOLD_DISK="$OPTARG" ;;
      j) FORMAT="json" ;;
      h) usage; exit 0 ;;
      :) usage >&2; die "opsi -$OPTARG membutuhkan argumen" ;;
      \?) usage >&2; die "opsi tidak dikenal: -$OPTARG" ;;
    esac
  done
  [[ "$THRESHOLD_DISK" =~ ^[0-9]+$ ]] || die "ambang disk harus berupa angka"
  disk="$(disk_usage_pct)"; mem="$(mem_used_pct)"; procs="$(proc_count)"
  status="OK"; ((disk >= THRESHOLD_DISK)) && status="PERINGATAN"
  if [[ "$FORMAT" == "json" ]]; then
    printf '{"host":"%s","disk_pct":%s,"mem_pct":%s,"proc":%s,"status":"%s"}\n' \
      "$(hostname)" "$disk" "$mem" "$procs" "$status"
  else
    printf '%-20s : %s\n'   'Host'             "$(hostname)"
    printf '%-20s : %s%%\n' 'Pemakaian disk'   "$disk"
    printf '%-20s : %s%%\n' 'Pemakaian memori' "$mem"
    printf '%-20s : %s\n'   'Jumlah proses'    "$procs"
    printf '%-20s : %s\n'   'Status'           "$status"
  fi
  [[ "$status" == "OK" ]] || return 2
}
main "$@"

#!/usr/bin/env bash
# setup.sh — versi MODULAR: fungsi bersama di lib/common.sh + logging terstruktur.
set -euo pipefail
APP_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
# shellcheck source=lib/common.sh disable=SC1091
source "$APP_DIR/lib/common.sh"
VENV_DIR="$APP_DIR/.venv"
PORT="${PORT:-5000}"
log_info "[1/5] Memeriksa prasyarat..."
require_cmd python3
require_cmd curl
python3 -c 'import sys; sys.exit(0 if sys.version_info >= (3, 10) else 1)' \

#!/usr/bin/env bash
# healthwatch.sh — CHALLENGE "Health Watcher": pantau /health, MTTR, ringkasan sesi.
set -euo pipefail
INTERVAL=5
URL="http://127.0.0.1:5000/health"
LOG_FILE="${LOG_FILE:-/tmp/healthwatch.log}"
CHECKS=0; INCIDENTS=0; TOTAL_DOWN=0; DOWN_SINCE=0; PREV_STATE="UP"
usage() {
  cat <<USAGE
healthwatch.sh — pemantau endpoint /health
  --interval N   Jeda antar pemeriksaan (detik, default 5, > 0)
  --url URL      URL dipantau (default $URL)
  -h, --help     Bantuan
Exit: 0 tanpa insiden, 2 bila ada insiden
USAGE
}
die() { echo "GALAT: $*" >&2; exit 1; }
iso_now() { date '+%Y-%m-%dT%H:%M:%S%z'; }
while [[ $# -gt 0 ]]; do
  case "$1" in
    --interval) [[ $# -ge 2 ]] || die "--interval butuh nilai"; INTERVAL="$2"; shift 2 ;;
    --url)      [[ $# -ge 2 ]] || die "--url butuh nilai"; URL="$2"; shift 2 ;;
    -h|--help)  usage; exit 0 ;;
    *) usage >&2; die "argumen tidak dikenal: $1" ;;
  esac
done
[[ "$INTERVAL" =~ ^[0-9]+$ ]] || die "--interval harus bilangan bulat"
((INTERVAL > 0)) || die "--interval harus > 0"
[[ "$URL" =~ ^https?:// ]] || die "--url harus http(s)://"
print_summary() {
  echo; echo "===== RINGKASAN SESI HEALTH WATCHER ====="
  local avail="100.00"
  ((DOWN_SINCE > 0)) && TOTAL_DOWN=$((TOTAL_DOWN + ($(date +%s) - DOWN_SINCE)))
  local total=$((CHECKS * INTERVAL))
  ((total > 0)) && avail=$(awk -v d="$TOTAL_DOWN" -v t="$total" 'BEGIN{printf "%.2f",(t-d)/t*100}')
  printf '%-24s : %s\n' "Jumlah pemeriksaan" "$CHECKS"
  printf '%-24s : %s\n' "Jumlah insiden" "$INCIDENTS"
  printf '%-24s : %s detik\n' "Total waktu padam" "$TOTAL_DOWN"
  printf '%-24s : %s%%\n' "Ketersediaan" "$avail"
  ((INCIDENTS > 0)) && exit 2 || exit 0
}
trap print_summary SIGINT
echo "Memantau $URL setiap ${INTERVAL}s — Ctrl+C untuk berhenti."; : > "$LOG_FILE"
while true; do
  s=$(date +%s%N)
  if curl -fsS --max-time "$INTERVAL" "$URL" >/dev/null 2>&1; then state="UP"; else state="DOWN"; fi
  e=$(date +%s%N); rt_ms=$(((e-s)/1000000)); CHECKS=$((CHECKS+1))
  printf '%s status=%s rt_ms=%s\n' "$(iso_now)" "$state" "$rt_ms" | tee -a "$LOG_FILE"
  if [[ "$state" == "DOWN" && "$PREV_STATE" == "UP" ]]; then
    DOWN_SINCE=$(date +%s); INCIDENTS=$((INCIDENTS+1))
    echo "  !! INSIDEN #$INCIDENTS dimulai $(iso_now)" | tee -a "$LOG_FILE"
  elif [[ "$state" == "UP" && "$PREV_STATE" == "DOWN" ]]; then
    m=$(( $(date +%s) - DOWN_SINCE )); TOTAL_DOWN=$((TOTAL_DOWN+m)); DOWN_SINCE=0
    echo "  >> PULIH $(iso_now) — MTTR: ${m} detik" | tee -a "$LOG_FILE"
  fi
  PREV_STATE="$state"; sleep "$INTERVAL"
done
